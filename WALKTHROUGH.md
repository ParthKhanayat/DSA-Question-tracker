# DSA Tracker - Architecture & Setup Walkthrough

This document contains everything you need to understand how this application was built, how it works, and how to continue development or deploy it in the future.

---

## 1. Project Overview & Features

A full-stack, cloud-synced web app designed to track Data Structures & Algorithms (LeetCode) problem-solving and revisions based on problem freshness.

- **Autocomplete for 3,600+ LeetCode Questions:** Pulled from LeetCode algorithms database with difficulty badges (Easy, Medium, Hard).
- **Custom Question Support:** Add any custom problem not in the LeetCode catalog.
- **Custom Date Selection:** Set the initial solved date to today or pick any past date.
- **Freshness Classification:** Problems are automatically grouped by when you last solved or revised them:
  - 🟢 **Fresh** (0–7 days): Recently practiced, high retention.
  - 🟡 **Slipping** (8–21 days): Approaching need for review.
  - 🟠 **Stale** (22–60 days): Concepts may be fading; review recommended.
  - 🔴 **Ancient** (>60 days): Urgent revision needed.
- **Ping (Revise) Action:** One-click button on each card to refresh the question's `last_solved_date` to the current moment.
- **Multi-Device Cloud Sync:** Powered by Supabase (PostgreSQL + Auth).
- **Authentication:** Email & password authentication with secure Row Level Security (RLS).
- **Modern UI:** Glassmorphism, tailored dark mode, fluid micro-interactions, responsive grid.

## 3. Database Schema & Security (Supabase)

The database runs on PostgreSQL in Supabase. The table definition and Row Level Security (RLS) policies:

```sql
-- 1. Table schema
create table questions (
  id bigint generated by default as identity primary key,
  user_id uuid references auth.users not null,
  question_id text not null,
  name text not null,
  last_solved_date timestamptz not null
);

-- 2. Enable Row Level Security (RLS)
alter table questions enable row level security;

-- 3. Row Level Security Policies
-- Users can only select their own data
create policy "Users can view their own questions" 
  on questions for select 
  using (auth.uid() = user_id);

-- Users can only insert data assigned to their own user_id
create policy "Users can insert their own questions" 
  on questions for insert 
  with check (auth.uid() = user_id);

-- Users can only update data belonging to their own user_id
create policy "Users can update their own questions" 
  on questions for update 
  using (auth.uid() = user_id);
```

## 6. How to Deploy on Vercel

1. **Push to GitHub:**
   ```bash
   git init
   git add .
   git commit -m "Initial commit of DSA Tracker"
   # Link to your remote GitHub repo and push:
   git remote add origin https://github.com/<your-username>/<your-repo>.git
   git branch -M main
   git push -u origin main
   ```

2. **Deploy on Vercel:**
   - Log into [Vercel](https://vercel.com/) and click **Add New... -> Project**.
   - Import your GitHub repository.
   - Under **Environment Variables**, add:
